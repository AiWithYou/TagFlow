# TagFlow 2.0.0: データ保護と確認方法

## 更新・起動

既存の設定ファイルとプリセットはそのまま利用します。AI接続先・認証・課金経路は変更していません。追加の実行時依存ライブラリもありません。

```powershell
git pull --ff-only
.\start.bat
```

バージョンの確認（GUIを起動しません）:

```powershell
.\venv\Scripts\python.exe tagflow_entry.py --version
# TagFlow 2.0.0
```

## 画像・タグの転送

1. 同じフォルダの画像名を調べ、最も長く一致するstemへサイドカーを所属させます。
2. 出力先のstemを予約し、画像・テキスト・メタデータの全コピーを一時領域に作成します。
3. 既存ファイルを上書きしない方法で出力先へ配置します。同名回避で改名したときは、メタデータ内の既知のファイル名参照も修正します。
4. 移動の場合のみ、全ファイルの配置と入力の変更検査に成功してから元ファイルを削除します。
5. 削除が失敗したら削除済み原本を復元します。復元先に新しいファイルがある場合は上書きせず、復旧用コピーを残してエラーを通知します。

`foo.png` と `foo.en.png` が同居する場合、`foo.en.txt` と `foo.en.lora.txt` は後者の所有です。従来の前方一致だけでは前者の移動に巻き込まれました。

移動先が元フォルダと同じ場合は何もしません。コピーの場合は従来どおり `_1` などで別ファミリーを作ります。

## 復旧情報が残った場合

例外メッセージに「復旧用原本」がある場合、その `.tagflow-transfer-*` フォルダと出力先の画像・テキストを削除しないでください。`manifest.json` の `recovery_files` に、元のパスと現存するバックアップの対応が記録されます。

アプリを停止してから、各 `source` と `backup` を確認してください。元パスに別の内容のファイルがあるときは双方を保存し、必要な版を判断してから戻します。この版では自動復旧コマンドや自動削除は用意していません。

強制終了後の `.tagflow-lock-*` は自動的に奪い取らず、次の転送は別の連番名を選びます。残留ロックを削除する場合は、TagFlowで転送が一切動いていないことを確認してください。

## 性能・保証範囲

移動でも全ファイルを先にコピーするため、出力先に一式分の空き容量が必要です。同一ドライブ内の単純なリネームより遅くなる場合があります。POSIXのハードリンク非対応ファイルシステムでは、排他的コピーへのフォールバックにより一時的に追加の容量も使います。

ファミリー全体が一瞬で切り替わるわけではありません。通常の処理例外からの復旧を対象としており、停電・強制終了・外部アプリによる同時書き換えに対する完全なトランザクション保証はありません。転送中の画像・タグを別のアプリで編集しないでください。

シンボリックリンクの画像・サイドカー、所有者が曖昧な同一stem画像、大小文字だけ違うサイドカーは安全側に停止します。壊れたメタデータのあるファミリーは、改名が必要な転送では停止します。改名しないコピーでは元のバイト列を保持します。

## 監査

同一バイト列ならファイルサイズも同じなので、同サイズの画像群だけSHA-256を計算します。サイズが全て異なる場合は重複検査のハッシュ計算は0件になります。画像の妥当性検証は別処理で、既定では引き続き実行します。全画像のサイズが等しい場合、ハッシュ対象は減りません。

監査JSONの `hashed_image_count` で実際にハッシュを計算できた件数を確認できます。従来のJSONフィールドは維持しています。

ライブラリからは `audit_dataset(..., should_stop=callback)` で停止要求を渡せます。停止時は `AuditCancelled` 例外です。これはコアAPIの機能であり、今回GUIや既存CLIに停止ボタンを追加したものではありません。

## 自動テスト

```powershell
python -m pip install "requests>=2.31.0" "Pillow>=10.0.0"
python -m unittest discover -s tests -v
python -m compileall -q TagFlow.py tagflow_entry.py tagflow_core tools tests
python tagflow_entry.py --version
```

CIはWindows/Linux × Python 3.11/3.13。テストには途中コピー失敗、他プロセス相当の同名ファイル割り込み、原本削除失敗、復旧先競合、並行コピー、読み取り専用ファイル、Unicode・ドット付き画像名、監査の読み取りエラー・停止を含みます。OS固有ケースは対象OSのみで実行します。

GUIを実機で確認する場合は、原本ではなく小さなテスト用フォルダでコピー・移動・同名回避を試し、画像・基本caption・翻訳caption・メタデータが揃っていることを確認してください。AI実推論・WindowsのGUI操作は、コアの単体テストとは別の確認項目です。
